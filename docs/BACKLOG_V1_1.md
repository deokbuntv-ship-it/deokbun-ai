## ⚠ V1 후보 — 미루면 손해가 누적되는 것

### ~~궁합 공유 카드~~ — **완료 (2026-09-05)**

- **무엇**: 궁합 결과를 이미지 카드로 만들어 공유. 받은 사람이 링크로 들어와 자기 궁합을 본다.
- **왜 V1 후보인가**: **출시 시점부터 바이럴 경로가 필요하다.** 늦게 붙일수록 그동안의 궁합
  사용자가 전부 공유 없이 지나가고, 그 손해는 되돌릴 수 없다. 다른 백로그 항목과 성격이 다르다.
- **이미 있는 것**: 궁합 상담 완성 · `report_shares` 테이블 + 공유 토큰 RPC ·
  `/shared-report/[token]` 화면 · `ShareReportSheet`
- **없는 것**: 궁합 전용 카드 렌더링(이미지 생성), 공유 진입 후 전환 경로
- **완료 (2026-09-05)**: 조사해 보니 **공유 경로는 이미 전부 있었다** — 궁합은 `consultation_reports` 에 `report_type='compatibility'` 로 저장되고 `/report/[id]` 의 `ShareReportSheet` 로 공유된다. 정말 없던 것은 **카드**(메신저가 클릭 전에 렌더하는 미리보기)였고, `/shared-report/[token]` 에 `SeoHead` 가 없어 루트 메타가 나가고 있었다.
  **결과를 카드에 넣지 않기로 했다** — 카톡 카드는 대화방 전체에 렌더되므로 결론 한 줄도 두 사람의 사적 정보다. 상세와 근거는 `PROJECT_STATE.md` §7.18-D. E2E 14/14.
- **재설계 (2026-09-06, 오너 정정)**: "카드에 아무것도 넣지 않는다"는 과했다 — 아무도 누르지 않으면
  기능 자체가 무의미하다. **익명 미리보기를 열었다**: 링크를 받은 사람이 로그인 없이 **결론 문단**을
  보고, 그 아래 "전체 보기"로 간편가입한다. 전체 읽기 권한은 그대로 두고 **별도 RPC 를 좁게 열었다**.
  상세 `PROJECT_STATE.md` §7.19, E2E 19/19.
- **남은 것 2가지 (둘 다 오너 대기, 둘 다 급하지 않음)**
  - **카드에 결론 한 줄** — 정적 export 라 서버 없이는 불가능하다. Vercel 함수 1개면 되지만 새
    엔드포인트라 오너 승인 사안(`OWNER_TODO.md` C11b). **누른 뒤에는 이미 결론이 보이므로 급하지 않다.**
  - **카카오 SDK 네이티브 공유 버튼** — `OWNER_TODO.md` C11. 없어도 링크 붙여넣기로 카드는 뜬다.

## A. 상품 · 수익

### A1. PLUS 구독

- **미룬 이유**: 정책값(가격·지급덕·이월)을 정할 **실사용 데이터가 없고**, IAP 가 열리기 전에는
  판매 자체가 불가하다. 단품 3티어로 출시해 데이터를 보고 설계한다 (2026-09-02 오너 결정).
- **확정된 제약 하나**: **구독은 대용량 티어의 ₩165.8/덕보다 싸야 한다.** 그것보다 비싸면
  구독할 이유가 없다. 그 외 숫자는 전부 미정.
- **이미 있는 자산 (지우지 말 것)**: `duk_ledger` 의 `PLUS` 버킷 · reason `PLUS_GRANT` ·
  **빈 테이블 `plus_entitlements`** · `economy_policy.plus_monthly_duk` / `plus_duk_expiry_seconds`
  (둘 다 null=TBD) · `CATALOG.PLUS_MONTHLY` · `SubscriptionState` 타입 · 차감 순서 PLUS→REWARD→PAID
- **다시 볼 시점**: **IAP 개통 + 단품 판매 1~2개월치 데이터 확보 후**
- **선행**: IAP

### A2. A3 설치 유입 (deferred attribution)

- **미룬 이유**: 광고 클릭 → 스토어 → 설치 → 첫 실행 경로에는 **URL 이 없다.** 딥링크로는
  원리적으로 풀 수 없고, Android 는 Play Install Referrer, iOS 는 Apple Search Ads 외에는
  **유료 3자 SDK(Branch/AppsFlyer/Adjust)** 가 필요하다. 개인정보 처리방침·데이터안전 폼도 바뀐다.
- **다시 볼 시점**: **광고비를 실제로 집행하기 시작한 뒤.** 그 전에는 측정할 유입이 없다
- **선행**: Universal/App Link(`OWNER_TODO.md` A3) · 광고 집행
- **규모**: 大

### ~~B1. 변곡점 알림~~ — **V1 으로 옮겼다. 인앱은 2026-09-07 완료**

- **무엇이 바뀌었나**: "푸시가 개통돼야 보낼 수단이 있다" 고 적었는데 **인앱은 이미 수단이 있었다.**

  있고, `NOTIFICATION_TYPES` 에 `TURNING_POINT` 가 **이미 예약돼 있었다.** 생산자만 없었다.

## D. 엔진 · 품질

### D1. 용신 교리 확장

- **무엇을 다룰 것인가** (`docs/YONGSHIN_CONSISTENCY_AUDIT.md` 가 출발점):
  - **강약 임계값 부재** — 뿌리 존재 여부 하나로 갈린다. 중간 상태가 없다
  - **`OFFICER`·`RESOURCE` 가 용신이 될 수 없는 구조** — 억부 사다리의 필연적 결과
  - **조후 영구 미발화** — 정본 규칙이 없어 코드가 도달할 수 없다
  - **통관 후보가 `{WOOD, WATER}` 2원소로 닫혀 있다**
- **미룬 이유**: **교리 결정이지 코드 문제가 아니다.** 임계값을 몇으로 할지는 명리 판단이고,
  근거 없이 숫자를 넣으면 그게 더 나쁘다.
- **다시 볼 시점**: 오너가 교리 판단을 내릴 준비가 됐을 때
- **⚠ 조건부 승격**: **Premium 이 용신을 결론 근거로 쓰기 시작하면 즉시 V1 필수**로 올라간다.
  현재는 쓰지 않는다(`premiumEvidence.ts` 헤더가 명시)

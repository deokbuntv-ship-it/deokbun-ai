### APK 를 다시 빌드할 필요가 **없습니다**

로그인은 `supabase.auth.signInWithOAuth` 로 갑니다(`src/features/auth/services/authService.ts:42`).

것은 빌드와 무관합니다. **EAS 빌드 0회.**

### 구글 로그인이 실패하면 — 확인할 곳 한 군데

Supabase(staging) → Authentication → **URL Configuration → Redirect URLs** 에
`deokbunai://login-callback` 이 있는지 보십시오. 없으면 로그인 뒤 앱으로 못 돌아옵니다
(Supabase 가 Site URL 로 되돌려 보내고, 기본값은 `http://localhost` 입니다).

네이버 개발자센터 → 내 애플리케이션 → API 설정 → Callback URL 에
**`deokbunai://login-callback`** 이 등록돼 있어야 합니다. 없으면 네이버 화면에서 막힙니다.

## 4-2. 테스트 계정과 덕

### 순서

1. **APK 에서 구글로 로그인**하십시오. 이 첫 로그인이 계정을 만듭니다.
   (미리 만들어 드릴 수 없습니다 — 관리자 로그인 수단이 없고, 테스트 전용 우회 로그인을
   만드는 것은 이번 지시서가 금지했습니다.)
2. 로그인하면 **웰컴 +10덕**이 자동으로 들어갑니다(체크리스트 #5 가 그것입니다).
3. 10덕으로는 부족합니다. 아래 표대로 더 넣으십시오.

### 얼마나 필요한가 — 체크리스트를 다 돌리는 데 드는 덕

| 항목 | 덕 |
|---|---|
| #8 일반 상담 1세션 | 5 |
| #9 후속 질문 | 0 (같은 세션) |
| #10 턴 소진 | 0 |
| #12·#13 궁합 1세션 | 12 |
| 재시도·여유 | 20 |
| **합계 권장** | **50덕** (웰컴 10 + **40 추가**) |

⚠ #11·#13(덕 부족 화면)은 **잔액을 5 미만으로 내려야** 볼 수 있습니다. 마지막에 하십시오.

### 넣는 방법 — ㉮ 를 먼저 시도하십시오

**㉮ 관리자 화면 (권장 — 감사 기록이 남는 정식 경로)**

이 계정이 staging 의 관리자면 앱/웹에서 관리자 → 경제 → **덕 조정**을 쓸 수 있습니다.
관리자가 아니면 staging SQL Editor 에서 한 줄 넣으십시오 (⚠ **staging 전용**):

```sql
-- 방금 로그인한 계정의 id 확인
select id, email from auth.users order by created_at desc limit 3;

-- 그 id 를 관리자에 넣는다 (staging 전용)
insert into public.admin_users (user_id) values ('<위에서 본 id>')
on conflict do nothing;
```

그 뒤 앱을 껐다 켜고 관리자 화면에서 **+40덕**, 사유는 `실기기 QA 2026-09-10` 으로 넣으십시오.
이 경로는 `admin_adjust_duk` 를 타서 **원장 + 감사 기록**이 함께 남습니다.

**㉯ ㉮가 안 될 때 (SQL Editor 직접)**

```sql
select public.grant_duk('<user id>', 40, 'REWARD', 'ADMIN_ADJUSTMENT', 'qa-2026-09-10', null);
```

⚠ 이 경로는 **감사 기록(admin_audit)이 남지 않습니다.** 원장에는 남습니다.
㉮가 안 됐다는 것을 결과지에 적어 주십시오.

그 변경이 들어간 뒤에 한 번 다시 빌드하는 것이 맞습니다. **이번 EAS 빌드 사용: 0 / 상한 1.**

# 오너 런북 — Google Play Console (2026-09-10)

> ⚠ **콘솔 화면 이름은 바뀌었을 수 있습니다.** 아래 메뉴 이름이 안 보이면 비슷한 이름을

>
> ⚠ 구글 개발자 계정은 이미 있습니다. 애플은 대기 중이라 이 문서에 없습니다.

## A. 지금 바로 할 수 있는 것

### A-1. 개발자 이름 변경

Play Console → **설정** → **개발자 계정** → **계정 세부정보** → **개발자 이름**

스토어에 표시되는 이름입니다. 앱 이름과 별개입니다.

### A-2. 결제 프로필(조직) · 판매자 계정

Play Console → **설정** → **결제 프로필** (또는 **수익 창출** → 결제 설정)

| 칸 | 넣을 값 |
|---|---|
| 사업자 유형 | 조직(법인) |
| 주소 | **등기부 본점 — 의장로 146, 1121호** |

> ⚠⚠ **주소가 두 개라 반려될 수 있습니다.**
> 사업자등록증 주소(강석로)와 등기부등본 본점 주소(의장로 146, 1121호)가 다릅니다.
> 서류 인증에서 반려되면 **등기부등본으로 대체할 수 있는지 구글에 문의**하십시오.
> (Play Console → 도움말 → 지원팀 문의 → 계정·결제 프로필)
>
> 문의 문구 예:
> > 법인 등기부등본상 본점 주소와 사업자등록증상 주소가 다릅니다.
> > 결제 프로필의 주소 인증을 **법인 등기부등본**으로 진행할 수 있는지 확인 부탁드립니다.

⚠ 판매자 계정이 승인돼야 인앱 결제를 붙일 수 있습니다. **가장 오래 걸리는 단계이니
먼저 시작하십시오.**

### A-3. 앱 만들기

Play Console → **모든 앱** → **앱 만들기**

| 칸 | 값 |
|---|---|
| 앱 이름 | 덕분이 |
| 기본 언어 | 한국어 |
| 앱 또는 게임 | 앱 |
| 무료 또는 유료 | **무료** (인앱 상품은 별개입니다) |

> ⚠⚠ **패키지명 `com.deokbun.app` 은 영구입니다.** 한 번 올리면 바꿀 수 없고, 같은 이름을
> 다시 쓸 수도 없습니다. 앱을 만들 때가 아니라 **첫 AAB 업로드 때** 확정됩니다.
> 그 전에 오타가 없는지 `app.json` 의 `expo.android.package` 와 대조하십시오.

### A-4. 콘텐츠 등급 설문

Play Console → 앱 → **정책** → **앱 콘텐츠** → **콘텐츠 등급**

입력 자료: **`docs/STORE_READINESS_2026-09-10.md` §5-3**.
그 표는 **사실만** 적어 두었습니다. 등급 판단은 오너가 합니다.

⚠ 특히 조심할 세 칸:
1. **디지털 구매** — "있음" 으로 답하십시오(덕 인앱 구매 예정).
2. **사용자 생성 콘텐츠 공유** — 리포트 링크 공유가 있습니다. 다만 **받는 사람도
   로그인해야** 열립니다. 공개 게시판·댓글은 없습니다.
3. **광고** — "있음" 입니다(자체 광고).

### A-5. 데이터 보안

Play Console → 앱 → **정책** → **앱 콘텐츠** → **데이터 보안**

초안: **`docs/STORE_READINESS_2026-09-10.md` §5-2** 의 표를 그대로 옮기십시오.

⚠ **[법률 검토] 로 표시된 두 칸은 변호사 확인 전에 확정하지 마십시오**:
① 국외 이전(OpenAI 는 미국) ② 거래기록 보존 기간.
데이터 보안 양식은 **거짓이면 앱이 내려갑니다.** 모르면 보수적으로 적으십시오.

### A-6. 스토어 등록정보 초안

Play Console → 앱 → **성장** → **기본 스토어 등록정보**

| 칸 | 준비물 |
|---|---|
| 앱 이름 (30자) | 덕분이 |
| 간단한 설명 (80자) | 아래 초안 |
| 자세한 설명 (4000자) | `docs/STORE_READINESS_2026-09-10.md` §5-1 B-2 의 차별점 초안을 풀어 쓰십시오 |
| 아이콘 512×512 | `assets/images/` 에서 만듭니다 |
| 그래픽 이미지 1024×500 | 필요 |
| 스크린샷 (폰 2장 이상) | **실기기 QA 때 찍은 것을 쓰십시오** |

**간단한 설명 초안** (80자 이내):

> 사주·자미두수·기문둔갑 계산 결과를 근거로 풀어 주는 AI 명리 상담

⚠ **결과를 단정하는 문구, 불안을 자극하는 문구를 넣지 마십시오.** 앱 안의 톤 규칙과
스토어 문구가 어긋나면 그 자체가 심사 소재가 됩니다.

## C. 결제 빌드를 올린 뒤 (다음 지시서)

⚠ 이 단계는 **결제 권한이 들어간 빌드가 Play Console 에 올라간 뒤**에만 가능합니다.
설계는 `docs/STORE_READINESS_2026-09-10.md` §5-4 에 있습니다.

1. **내부 테스트 트랙에 AAB 업로드**
   Play Console → 테스트 → **내부 테스트** → 새 버전 만들기
2. **Play 앱 서명** 사용 (기본값). EAS 키스토어를 **업로드 키**로 등록
   ```bash
   npx eas credentials --platform android
   ```
   ⚠ 키스토어를 잃어버리면 업데이트를 못 올립니다. **백업을 받아 두십시오.**
3. **인앱 상품 3종 생성**
   수익 창출 → 제품 → **인앱 상품**

   | 상품 ID | 이름 | 가격 |
   |---|---|---|
   | `duk_first_20` | 첫 충전 20덕 | ₩2,900 |
   | `duk_base_50` | 기본 50덕 | ₩9,900 |
   | `duk_large_120` | 넉넉 120덕 | ₩19,900 |

   ⚠ **상품 ID 는 소문자·숫자·밑줄·마침표만** 되고, **한 번 만들면 못 바꾸고 재사용도
   안 됩니다.** (콘솔 입력 도움말로 규칙을 다시 확인하십시오 — 이 규칙은 미확인입니다.)
4. **라이선스 테스터** 등록
   설정 → 라이선스 테스트 → 테스터 계정 추가 (실결제 없이 구매 흐름 확인)
5. **서비스 계정 연결** (서버 검증용)
   설정 → API 액세스 → Google Cloud 프로젝트 연결 → 서비스 계정 만들기 →
   **재무 데이터 보기 · 주문 관리** 권한 부여 → JSON 키를 **Supabase Edge 시크릿**으로
   ⚠ **JSON 키를 레포에 넣지 마십시오.** Edge 시크릿에만 넣습니다.
6. **RTDN(실시간 개발자 알림)**
   수익 창출 설정 → 실시간 개발자 알림 → Pub/Sub 주제 입력 →
   `google-rtdn` Edge 를 구독자로 연결

### 1-2 정리 ① 시간 — 24시간이 지나면 원문을 지우고 키만

- **왜 키만 남겨도 되나**: `acquire_paid_request` 는 재생 창(`expires_at`)이 지난 행을 이미 **새 요청으로** 받는다
  (같은 request_id 가 오면 다시 생성). 창이 지난 원문은 재전송 방지에 **아무 역할이 없다**. 남기는 최소 값 =
  사용자 · 종류 · request_id · 상태(`EXPIRED`) · 시각. `EXPIRED` 는 재생 경로 어디에서도 읽히지 않는다(계약 테스트).
- **주기 작업**: 기존 `run_*` 패턴(서비스 전용 SQL 함수 — `run_birthday_notifications` 와 같은 모양)을 따랐다 →
  `run_answer_retention(p_limit)`. 호출은 **pg_cron** 이 SQL 을 직접 부른다(매시 17분). Edge 를 거치지 않으니
  크론 설정에 비밀값이 들어가지 않는다. (기존 `run-*` Edge 가 있는 이유는 푸시·메일 공급자 호출 때문이다 —
  이 작업은 DB 안에서 끝난다.)
- 같은 작업이 **해지·만료된 공유의 스냅샷**도 비운다(읽는 함수가 없다). 이를 위해 스냅샷 동결 트리거에 예외
  하나 — "서버가, 죽은 공유의, 스냅샷을 **비우는** 것" — 를 더했다. 클라이언트는 여전히 한 글자도 못 바꾼다.

### 1-3 정리 ② 대화 삭제 — 즉시

`conversations` 의 **BEFORE DELETE** 트리거(대화→답 연결인 `consultation_decisions` 가 CASCADE 로 사라지기 **전**):

1. 그 대화의 답 원문 → `EXPIRED`
2. 그 답의 증인 → 삭제 (지운 대화에서 나온 해시)
3. 그 대화 리포트의 공유 → **해지 + 스냅샷 비움**

**공유를 해지하는 근거**: 대화를 지운다는 것은 그 내용을 치우겠다는 뜻이다. 링크를 받은 사람에게 계속 보이면
삭제가 반쪽이 된다. 리포트 자체는 우편함 보관물이라 남긴다(설계 20260818) — 지울지는 C4.

⚠ **범위**: 연결은 서버 판단 기록에만 있다. 거기 없는 답(요약 · 대화 없이 온 요청 · 거절 등)은 ① 의 24시간
정리가 지운다. staging 커버리지 — 상담 **619/710(87%)** · 궁합 **25/34(74%)** · 요약 **0/6** → C3.

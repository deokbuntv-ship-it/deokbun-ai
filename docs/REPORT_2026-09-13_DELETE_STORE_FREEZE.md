## 4. ⚠ 패키지에서 찾은 결함 — 실사이트 웹과 `chat` 의 계약이 다르다 (C1 · M15)

**사실 (레포 · 원격 조회로 확인)**:
- 실사이트 = 원격 `main` = **`28c406a`** (2026-08-15, `git ls-remote` 로 확인). 그 웹은 상담을 `{messages, requestId}` 로 보낸다
  (`supabaseEdgeLLMAdapter` ← `chat.tsx`).
- 이 패키지의 `chat`(서버 신뢰 계약, `4343d8a` 2026-08-17 이후)은 `question` 이 없으면 **`400 INVALID_INPUT`**. 옛 `chat` 은
  반대로 `messages` 가 없으면 400. → **웹과 `chat` 은 함께 바꿔야 한다.**
- production `chat` 이 지금 어느 버전인지는 **알 수 없다**(접속 금지). 2026-09-06 승격 계획서가 `chat` 을 1차 배포 대상으로
  적었고 결과가 "Edge 13 ACTIVE" 라, 그때 올라갔다면 **실사이트 상담은 지금도 400 으로 실패하고 있다.**

**직전판의 문제**: ⑤ 에서 `chat` 을 먼저 올리고, ②-6 에서 "웹이 아직 옛 코드여도 상담은 됩니다" 라며 실사이트 상담으로 증인
행을 확인하게 했다. 어느 경우든 기대가 나오지 않는다(옛 `chat` 이면 증인 행이 안 생기고, 새 `chat` 이면 상담이 실패). 멈춤
신호가 "상담이 실패하면 21 → 20 되돌리기" 였으므로 **불필요한 되돌리기**로 이어질 수 있었다 — 21 을 되돌리면 #25 가 다시 열린다.

**고친 것 (동결본)**:
1. ⑤ 는 Edge **3개**(`verify-purchase` · `google-rtdn` · `iap-reconcile`). `chat` 은 **⑦-2 — 실사이트가 새 화면인 것을 본 직후**.
2. ②-6 의 상담 확인 → **⑦-3**(새 웹 + 새 `chat`): 상담 1회 → 대화 연결 · 증인 → [상담 삭제] → `EXPIRED`. 실패해도 DB 는
   되돌리지 말고 CTO 에게.
3. ① **1-9**(기록만): 실사이트 상담 1회 — 성공이면 production `chat` 은 옛 버전(⑦-1~⑦-2 사이 1~2분 실패 창), 실패면 이미
   새 버전(지금 실사이트 상담이 안 되는 상태 — ⑦ 이 고친다).
4. 되돌리기 절: "`chat` 을 병합 전 `main` 버전으로 되돌리면 새 웹 상담이 모두 실패 — 웹을 되돌릴 때만 함께".

# V1 출시 컷라인 — 무엇을 하고 무엇을 안 하는가

> **컷라인 밖 작업은 하지 않는다.**
> **새 작업을 추가하려면 먼저 이 문서에서 분류를 받아야 한다.**
>
> 이 문서가 존재하는 이유: 남은 작업이 걸러진 적이 없어 **"언제 끝나나" 에 답할 수 없었다.**
> 체크리스트는 "무엇이 있는가" 를 세고, 이 문서는 **"무엇이 필요한가"** 를 가른다.
>
> 2026-09-06 신설. 분류의 정본은 이 문서 하나다 —
> `FEATURE_MASTER_CHECKLIST`(구현 상태) · `KNOWN_RISKS`(위험) · `OWNER_TODO`(오너 액션)는
> **각자의 것만 소유하고 컷라인 판정은 여기를 참조한다.** 같은 판정을 두 곳에 적지 않는다.

## 분류 기준

| 등급 | 뜻 | 판정 질문 |
|---|---|---|
| **BLOCKER** | 없으면 **출시 자체가 불가능** | 스토어가 거절하는가 · 결제가 불가능한가 · 법적으로 필수인가 · 사용자가 앱을 못 쓰는가 |
| **SHIP** | 출시는 되지만 **첫 사용자 경험이 망가진다** | 처음 온 사람이 이것 때문에 이탈하는가 |
| **V1.1** | 출시 후에 해도 **손해가 없다** | "있으면 좋다" 는 전부 여기다 |
| **DROP** | 안 해도 된다. **목록에 있었을 뿐** | 다른 것으로 대체되거나 애초에 필요가 없었다 |

적용한 세 가지 렌즈:

1. **"있으면 좋다" 는 SHIP 이 아니라 V1.1 이다.** SHIP 은 *없으면 망가지는 것*만이다.
2. **운영자는 1명이다.** 관리자 기능의 결함은 **말로 전달되고 우회된다** — 낯선 사용자가 겪는
   결함과 같은 무게로 다루지 않는다. 관리자 편의는 기본이 V1.1 이다.
3. **사용자가 도달하지 않는 화면은 SHIP 이 아니다.**
4. ⚠ **스토어 정책은 레포에서 확인할 수 없다** — 해당 항목은 `[확인 필요]` 로 표시하고 §8 로 보낸다.

## 1. BLOCKER — 이것만 하면 출시 가능

**체크리스트 9항목 + 체크리스트 밖 3건 = 12.**
체크리스트 9항목의 내역: **순수 오너 5**(7.1·7.2·7.4·9.4·8.3) · **순수 개발 2**(4.3·4.4) ·
**공동 2**(4.2 IAP · 9.3 자산). 목록 밖 3건은 개발자 계정 · production 반영 · 실기기 빌드다.

이 분기가 체크리스트 BLOCKER 를 **9 → 6** 으로 바꾼다. §8 Q1.

### 임계 경로

**개발자 계정 → 스토어 IAP 상품 등록 → IAP 클라이언트(大) → 영수증 검증기(中) → 실기기 결제
테스트 → 제출.**

- **계정이 임계 경로의 머리다.** 승인 대기가 있고, 그 뒤의 사슬이 가장 길다.
- **IAP 클라이언트 코드는 계정 없이 쓸 수 있지만 테스트할 수 없다.** 스토어에 상품이 등록돼야
  구매 플로가 돌아간다 — 그래서 "먼저 코드를 써 두는" 병렬화의 이득이 제한적이다.
- 나머지 BLOCKER 4건(①②③④)은 **계정과 완전히 독립**이고 서로도 독립이다. 지금 전부 시작할 수 있다.

### 남은 거리 — 정직하게

⚠ **날짜는 추정하지 않는다**(오너가 출시일을 못 박지 않기로 했다). 작업 단위로만.

| | 개발 | 오너 |
|---|---|---|
| **계정이 오늘 생긴다고 가정** | 大 1 · 中 1 · 小 1 + 실기기 검증 1묶음 | 설정 3건(애플·IAP상품·연령등급) |
| **계정 없이 지금 가능** | production 반영 1묶음 · 스토어 자산 교체(디자인 수급 후) | 승인 1 · provider 확인 1 · 법률 검토 1 |

**비중**: 체크리스트 BLOCKER 9항목 중 **오너만으로 닫히는 것이 5개**, 개발만으로 닫히는 것이 2개,
공동이 2개다. 개발 쪽 무게중심은 **IAP 하나에 몰려 있고**, 그것을 빼면 남는 개발 작업은
production 반영과 자산 교체뿐이다.

> **한 줄 요약: 지금 개발이 막혀서 못 나가는 것이 아니라, 계정과 결정이 없어서 못 나간다.**

## 9. 이 문서를 갱신하는 규칙

- **새 작업이 생기면 먼저 여기서 분류를 받는다.** 분류 없는 작업은 하지 않는다.
- 등급이 바뀌면 **여기만** 고친다. 다른 문서는 이 문서를 참조한다.
- 항목이 닫히면 지우지 말고 **취소선 + 닫힌 날짜**를 남긴다.
- ⚠ **BLOCKER 를 늘리려면 §분류 기준의 네 질문 중 하나에 "예" 라고 답할 수 있어야 한다.**
  답할 수 없으면 SHIP 이하다.
